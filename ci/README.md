# Portable compatibility evidence

This is a maintainer-only GitHub source surface. None of `ci/` or `.github/` ships in the Doctor tarball. Existing private tests and artifacts are not dependencies and must not be uploaded.

## Execution

The fixed workflow runs ubuntu-24.04, macos-15 and windows-2022 × Node 22.19.0 / 24 × Host 0.2.1-rc.2 / 0.2.1-rc.4. The receipt records actual OS release, architecture, Node and loaded package versions. Node 24 means the actual 24.x selected by setup-node, not an invented patch version. GitHub cancelled the preceding macos-14 jobs before execution because that runner configuration was unsupported; macos-15 is the documented standard arm64 label. This changes the current native runner target, not historical macos-14 evidence or product support claims. See [GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

```sh
node ci/compatibility.mjs --host 0.2.1-rc.2 --output "$RUNNER_TEMP/doctor-summary"
```

The driver creates one OS temporary domain, an isolated Home/workspace/npm configuration/cache and exact SDK fixture. It packs the explicit runtime whitelist, checks tarball inventory, installs that tarball and these public SDK packages with lifecycle scripts disabled:

- `@deepseek-ai/cordis@4.0.5`
- `@deepseek-ai/dsh@HOST_VERSION`
- `@deepseek-ai/dsh-credentials-local@HOST_VERSION`
- `@deepseek-ai/dsh-host-webserver@HOST_VERSION`
- `@deepseek-ai/dsh-client-connection@HOST_VERSION`

Their normal npm dependency closure is external SDK code. No new product dependency or model API key is needed. Network installation failure fails the row; it is not a skip or pass.

`host-http.mjs` is the extracted real Cordis/BrowserAuth HTTP core formerly in the private frontend transport script. It retains 26 owner/auth/Origin/Host/body-limit/epoch/sequence/privacy/unload checks. `platform-checks.mjs` adds 16 fixture groups: path mapping, CLI roots/links, file URLs, pnpm permissions and interpreter chain, DSH-only log discovery, workspace/temp cleanup, proxy/BOM/log repair backup/recheck/rollback and protected link targets. `matrix-contract.mjs` reuses the established evidence judge. Platform overrides test branches, not native operating systems.

Public CI checks installed runtime bytes exactly. For the manifest it permits only the observed removal of exactly one final LF and also requires exact parsed JSON values; other formatting or byte changes fail. It executes that installed candidate inside real SDK Host/HTTP. Graph rows and repair inputs are explicit fixtures; no desktop, visual, human-click, complete shipped preset or real-user repair result is claimed. Plugin-enable retains the existing private regression coverage; CI does not invent a second installer/recovery implementation.

A local cached-SDK reproduction may add `--runtime-root SDK_ROOT --prepared-package CANDIDATE_TGZ`. This read-only SDK mode runs staged source and records the supplied tarball hash, explicitly not npm installation or an Actions row. It never installs into an existing SDK/profile.

The checkout disables Git autocrlf conversion for that action only. Before Node setup, every tracked working-tree file must match its raw Git blob hash; CRLF-transformed content is not accepted as frozen source. This gate does not diagnose npm installation failures.

## Receipt and cleanup

The npm-install path records the actual setup-node npm version. Failed children additionally expose elapsed milliseconds, enumerated process error/signal, fixed npm error codes, registry HTTP status counts, tar-entry warning counts and output byte counts. Captured npm output is parsed in memory, never uploaded or persisted by this driver. No timing log is enabled, installation deadlines remain unchanged, and missing diagnostic matches do not prove a phase was never reached.

The parent counts only anchored `npm warn tar TAR_ENTRY_ERROR` / `npm WARN tar TAR_ENTRY_ERROR` prefixes already present in captured stderr. `tarEntryWarningEvidence` is `available` for a captured string/Buffer, `partial` when that captured stderr accompanies `ENOBUFS`, and `unknown` for missing or unreadable stderr; unknown counts remain null, while a known empty string yields zero and an empty map. `tarEntryErrnoCounts` accepts only a fixed errno immediately after that category followed by a colon. Missing or unrecognized errno goes to `OTHER`, which is not an identified system errno. Only observed fixed keys are emitted, and their nonnegative integer counts sum to `tarEntryWarningCount`; message tails, paths, URLs, arguments and stacks are not used to infer errno or included in the receipt. These are captured-prefix counts, not cumulative system errors, unique packages or current pending operations. Timeout or buffer exhaustion can leave only a prefix of the child's output. Zero means no matching warning was observed in that captured output, and positive counts do not prove the timeout's cause. Original exit codes, cleanup, the full SDK, scripts-disabled policy and 480-second deadline stay unchanged. r9 discarded its raw stderr; these new counts must not be backfilled into r9 evidence.

Only the npm-install child preloads this same CI driver, gated by a dedicated marker, exact npm CLI identity and isolated Home agreement; pack, Host and real profiles do not receive the marker or global NODE_OPTIONS. The observer records fixed timer phases and normalized package counters, never raw timer names, package locations or URLs. Fixed phase transitions persist immediately; package counters aggregate in memory and flush at most every five seconds. An atomic journal stays inside the temporary Home. The parent accepts at most 4KiB of regular, non-symlink, strictly validated fixed-key data; missing or invalid data remains unknown and does not alter npm's exit or the 480-second deadline. Timer ended means timing ended, not operation succeeded; only the original installation and receipt gates establish success.

Journal v4 adds a passive ordinary Node HTTP/HTTPS observation under the same isolated npm preload. Two public, Experimental diagnostics channels, `http.client.request.created` and `http.client.response.finish`, identify request creation and received headers; the latter is not body completion. The observer retains at most 1024 opaque active request identities, timestamps and response references. It listens only for public `end`/`close` and reads public `IncomingMessage.complete`; it does not read URLs, headers, methods, arguments, paths, stacks, private contexts or body bytes, and never calls `read`, `resume`, `pipe` or `destroy`. No error listener is installed. Own listeners and subscriptions are removed on termination/stop.

The fixed `http` sample counts created requests, observed headers, consumed-body ends and closes before an observed end. Live requests are separately classified as no headers, headers with raw message incomplete, or raw message complete but not yet consumed to end, with the oldest observed live age. A close-before-end is not automatically a transport error or success. `complete=true` means the raw HTTP message was received and parsed, not that cache, tar extraction or filesystem work finished; `complete=false` does not by itself prove a remote fault. No matched created/header events, malformed or repeated events, a cap breach or observer failure leave this independent sample strictly unknown rather than reporting full zero coverage. These are observed ordinary HTTP stages in this one npm process, not universal CONNECT/upgrade/protocol tracing or package counts. The 4KiB journal, five-second heartbeat, full SDK, disabled scripts, original exits and 480-second deadline are unchanged. Historical r9/r10 runs are not backfilled with this field.

Journal v4 retains a fixed activity sample on every phase flush and five-second heartbeat, even with no new timer event. It records the sample position/window, process CPU microseconds, main-loop active/idle milliseconds, and a bounded set of observed FSREQCALLBACK/FSREQPROMISE resource lifetimes. Hooks retain at most 4096 numeric IDs/timestamps, read no resource object or path, and perform no I/O or logging. Dropped resources remain counted; alive/oldest then describe only the tracked subset, not real OS pending requests or guaranteed disk waits. Destroy delivery can lag operation completion. CPU and event-loop figures have different scopes, include observer overhead, and a zero or tiny window does not prove idle or saturated work. Unavailable activity remains unknown without losing valid phase evidence or changing the installation gate.

For the verified graceful-fs 4.2.11 ABI only, the parent reads package metadata and passes the supported version to this isolated npm child. A passive sampler reads an already-published global Symbol queue; it never requires graceful-fs, wraps real fs, enables NODE_DEBUG, or reads queued functions/arguments or error paths/messages. At most 128 entries are classified by the fixed EMFILE/ENFILE/unclassified set, with explicit omitted count. These are queued entries at the sample time, not cumulative failures, unique packages or retry rates. Missing/unsupported metadata, an absent/non-array queue or a failed getter remains unknown rather than zero; unrecognized entries remain unclassified. A sampled empty queue does not rule out earlier transient pressure. This is diagnostic evidence only: full SDK installation, scripts-disabled policy, exit verdict and the 480-second deadline remain unchanged.

Only `summary.json` is uploaded. Its allowlisted fields bind revision (when available), canonical source file hashes, package version/tarball hash, actual runtime versions, step status/exit code, timestamps, counts and listener/Home cleanup. No raw stdout/stderr, environment dump, cookies/tokens, temporary absolute path, profile, SDK directory or log is uploaded. Failed children expose fixed codes only. Captured output remains inside the temporary domain and is discarded. Cleanup failure, missing versions, failed checks or bad receipts fail the run.

Each child has a bounded deadline. Parent removal deletes only its own unique temporary domain. A killed worker must not be represented as clean; `listenerClosed` stays false. Workflow has contents:read only, pinned action SHAs, no secret references, no credential persistence, no PR-target execution or writes. SDK installation runs only in the temporary fixture with npm lifecycle scripts disabled.
